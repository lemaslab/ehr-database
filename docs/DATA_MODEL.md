# Canonical data model, naming, and provenance

[← Repository overview](../README.md) · [Pipeline execution](PIPELINE_EXECUTION.md) · [Note metadata](CLINICAL_NOTES.md)

## Scope and grain

This repository harmonizes maternal–infant EHR data for **UF Health Gainesville (GNV)** and **Jacksonville (JAX)**. Canonical files are organized by site and domain. Each domain preserves its natural row grain:

| Domain | Grain | Canonical combined stem |
|---|---|---|
| Mother–baby linkage | One record per infant | `mom_baby_link_all_sites` |
| Delivery encounters | One record per infant | `delivery_encounter_all_sites` |
| Maternal diagnosis | Diagnosis event | `mom_icd_all_sites` |
| Infant diagnosis | Diagnosis event | `infant_icd_all_sites` |
| Maternal inpatient medication | Medication event | `mom_ip_all_sites` |
| Maternal outpatient medication | Medication/order event | `mom_op_all_sites` |
| Clinical-note metadata | Unique global note key | `clinical_notes_metadata_all_sites` |
| Maternal/infant laboratories | Laboratory observation | `mom_labs_all_sites`, `infant_labs_all_sites` |

Data are not expanded to one row per pregnancy unless an explicit, validated transformation calls for that. In particular, do not assign maternal note/lab events to a particular delivery solely by joining on a mother's ID.

## Canonical identifiers

- `site`: `GNV` or `JAX`
- `part_id_mom`: `AC-mom-*` at GNV, `DC-mom-*` at JAX
- `part_id_infant`: `AC-infant-*` at GNV, `DC-infant-*` at JAX
- `delivery_id`: delivery episode identifier generated by the mother–baby linkage
- `note_uid_global`: note-level global key in clinical-note metadata

**Do not assume that a similarly named note key generated in a separate UFRC Parquet pipeline matches `note_uid_global` until a crosswalk has been independently validated.**

## Paths and naming

Processed RDA files use a date-only suffix:

```text
data/
  cache/id_linkage_pipeline/         # resumable linkage/delivery RDS caches
  processed/
    GNV/<dataset>_YYYYMMDD.rda
    JAX/<dataset>_YYYYMMDD.rda
    COMBINED/<dataset>_YYYYMMDD.rda
    LAB_QC/lab_qc_YYYYMMDD.csv
    RELEASES/ehr_release_YYYYMMDD_HHMMSS/
logs/run_YYYYMMDD_HHMMSS/
```

Examples: `mom_icd_gnv_20261011.rda`, `clinical_notes_metadata_all_sites_20261011.rda`. New final filenames should not add `_linked`, `_final`, or an ad hoc timestamp. **Exception:** preserved lab *source extraction* RDAs may retain their extraction timestamp (for example `20261010_193021`); these are inputs to the canonical postprocessor, not the final release.

Within site tables, `site` is uppercase, while filenames use lowercase `gnv` and `jax`.

## Provenance and release versioning

The release-specific dataset and the source release are distinct concepts. Pin both the RDA release date and the raw inputs used to build it. Record source paths, file metadata, row counts, schema, variable names, code version, checksum and linkage QC. A successful file write does not by itself prove the file was built from the intended input cohort.

Review the source-inventory tool [00_raw_source_inventory.R](../code/run/00_raw_source_inventory.R): it detects declared file paths and read calls, but cannot guarantee every dynamic data source was read.

## Security

Raw files remain in approved, restricted storage. Do **not** commit patient-level tables, clinical-note text, lab records, raw-source data, or identifying values to GitHub. Logs, manifests and reports should be aggregate-only and reviewed for sensitive paths before sharing. The repository contains *code and documentation*, not a public distribution of the underlying EHR datasets.
